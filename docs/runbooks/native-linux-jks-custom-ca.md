# Native Linux PA Java truststore qualification

Scope: PA 12.10.1.1, Ubuntu 24.04.5 amd64, existing registered QA agent. The bundled Java truststore is `/opt/jitterbit/jre/lib/security/cacerts`, format **PKCS12**. The capability is called “JKS / custom CA” for continuity, but this file is not JKS-format. The user-supplied `jitterbitlabs_uk_certificate.pem` is a valid PEM X.509 **endpoint certificate** (`CA:FALSE`), not a CA; its explicit QA trust is requested for this phase.

The controlled command is `jbpa enterprise --config <validated QA config> --qa-verified-default-password --qa-endpoint-certificate --expected-agent-id 646830 --expected-agent-group-id 678370 --expected-agent-name 'automated-agent_2026-09-25 19:57:36.923' --expected-agent-group-name '7-Automated Infrastructure'`. Use `--dry-run` first. The QA configuration includes alias `qa-jitterbitlabs-uk-origin` and the certificate's DER SHA-256 fingerprint. Stage only a public-certificate copy under `/var/lib/jbpa/input`; do not commit certificate material or modify the original input. The QA password flag is restricted to the verified Ubuntu 24.04 / PA 12.10.1.1 tuple. Keytool receives it through an environment variable, not argv or output.

The branch checks the current package, existing credentials, exact about identity/version/group, current connection-check, core services, bundled keytool, store, certificate validity, fingerprint and alias before mutation. This `STEADY_STATE_EXISTING_AGENT` preflight requires no new restart or timestamp. An absent alias creates a new root-private backup under `/var/lib/jbpa/backups/<run-id>/cacerts`; source and backup hashes must match. The bundled keytool imports non-interactively, then verifies the alias fingerprint and changed store hash. A changed import triggers one restart with recorded T0 and uses `POST_CONFIGURATION_RESTART`: fresh Harmony identity/authentication, Agent Services, request flow, connection-check and all four core services are mandatory. Heartbeat, a new synchronization marker and service-status rows are supporting. A matching alias uses steady-state health and returns `NO_CHANGE` with stable hashes and no backup, import or restart.

If import or a mandatory post-change signal fails, the workflow restores the exact backup, verifies the original hash, restarts and uses `POST_ROLLBACK_RESTART`. A successful restore with all required health gates returns `JKS_CONFIGURATION_ROLLED_BACK`; an incomplete restore or health check returns `JKS_ROLLBACK_FAILED`. Missing sync lines or service-status rows alone do not trigger rollback. Preserve the structured result and inspect the agent before any further enterprise branch. Do not rerun install or registration to recover this truststore test.

The [Phase 2F summary](../phase-2f-summary.md) is the qualification status source. A `TESTED_LIVE` promotion requires both a changed import with all health gates and an identical second run returning `NO_CHANGE` with a stable store hash and no restart.
